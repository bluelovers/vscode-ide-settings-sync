## Context

當前同步 UI 允許使用者選擇多個 IDE 進行設定同步，但所有被選中的 IDE 都會被視為「同步來源」，未提供明確的「來源 IDE」選擇機制。這導致：

1. 使用者難以辨別設定資料的同步方向（來源 → 目標）
2. 可能導致無意的設定覆蓋與資料遺失
3. 同步邏輯缺乏明確的來源指定

## Goals / Non-Goals

**Goals:**
- 在每個 IDE 選項前方增加 Radio 選擇器，用於指定該 IDE 作為「來源 IDE」
- 來源 IDE 的設定將作為同步的來源資料，同步至其他目標 IDE
- 在 IDE 列表下方顯示目前被選擇的來源 IDE
- 將被選擇的來源 IDE 以不同顏色高亮顯示

**Non-Goals:**
- 不修改後端的同步邏輯（僅修改前端 UI）
- 不支援同時選擇多個來源 IDE
- 不修改現有的 checkbox 選擇邏輯（checkbox 仍用於選擇目標 IDE）

## Decisions

### 決策 1: 使用 Radio 而非 Checkbox 選擇來源 IDE

**選擇：** 在每個 IDE 項目前方使用 `<input type="radio">`

**理由：**
- Radio 確保同時只有一個來源 IDE，符合單一來源原則
- 與現有的 checkbox 選擇器（用於目標 IDE）形成明確區分
- 使用者直覺理解 radio = 唯一來源，checkbox = 多重選擇

### 決策 2: 來源 IDE 高亮顯示方式

**選擇：** 使用 CSS 類別 `.source-ide` 搭配不同背景色

**理由：**
- 不影響現有布局結構
- 可以靈活調整視覺樣式
- 易於實作動態切換效果

### 決策 3: 來源 IDE 狀態管理

**選擇：** 在前端組件狀態中管理來源 IDE 選擇

**理由：**
- 僅需修改前端 UI，不需要修改後端邏輯
- 使用者可即時看到選擇結果
- 同步時從前端傳遞來源 IDE 資訊至後端

## Risks / Trade-offs

### 風險 1: 未選擇來源 IDE 時的同步行為

**風險：** 使用者可能忘記選擇來源 IDE，導致同步行為不明確

**緩解：** 
- 在 UI 上預設選擇第一個 IDE 作為來源
- 顯示明確的來源 IDE 指示器

### 風險 2: 與現有 checkbox 邏輯衝突

**風險：** 新增的 radio 可能與現有 checkbox 產生視覺混淆

**緩解：**
- Radio 放置於 checkbox 左側，形成「來源 → 目標」視覺順序
- 使用不同顏色區分來源與目標選擇狀態
